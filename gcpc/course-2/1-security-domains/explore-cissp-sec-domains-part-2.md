# Notes
## Explore the CISSP Security Domains, Part 2
### The Last 4 Domains
#### IAM (Identity and Access Management)
- focused on access/authorization to keep data secure
- ensure users only have access to what they need
##### 4 Components of IAM (IAAA)
###### Identification 
- user identifying themselves, username, access card or other
###### Authentication 
- verifying a persons identity or claimed identity
###### Authorization
- after a user identity is confirmed
- determines level of access, likely based on role 
###### Accountability
- monitoring/recording user action
- *nonrepudiation* validates a user did commit an action
#### Security Assessment and Testing
- mainly conducting; security control testing, collecting/analyzing data, security audits to monitor; risks, vulnerabilities, threats
- weighing org goals against the controls effectiveness
- likely results in improving current controls, or implementing new ones
#### Security Operations
- conducting investigations/ implementing preventative measures
- this is where the controls from the security assessment would be implemented
- once a incident is identified, investigation begins
	- neutralize and contain threat first then gather evidence
	- identify when, how, and why the breach occurred
#### Software Development Security
- secure coding practices
- *Software development lifecycle* is an efficient process used to create secure applications and services 
	- each stage should undergo security reviews so it can be fully integrated rather than an after thought
